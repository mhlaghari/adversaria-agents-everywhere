## Hackathon slice — 2026-09-12

### Terminal edition (founder-directed scope extension)

`cli/` provides a standalone terminal version of capture → suggestions → approved
tasks → artifacts, using the hackathon's OpenRouter, Exa and Codex credits. Unlike
the desktop local-first contract below, this explicitly selected edition defaults
to cloud speech/LLMs through OpenRouter. Codex uses the installed CLI's login;
Exa queries are explicit (`--web`/`search`). Direct OpenAI API is optional. No local
model or Tauri/ML sidecar is required. Its own plaintext SQLite store is isolated
from desktop SQLCipher data. It supports microphone plus optional loopback input;
native desktop audio taps, diarization and desktop DB synchronization are outside
this terminal implementation. Details and live verification limits: `cli/README.md`.

### Desktop commitment slice

Commitments spoken during a recording are held in memory and presented for explicit approval. Only confirmed caption turns ending at a `silence` boundary are detected, on both Me/Them channels, with the pinned commitment patterns, owner/deadline captures, and normalized 60-second deduplication. Copilot-generated SAY text is not a detector input.

`commitment_approve(session_id, id, capability?)` creates a workspace task whose details start with `Caught live`, then kicks the existing autopilot when agents are unpaused. While paused, it creates an eligible queued task and reports `run_queued: false, agents_paused: true`. Prefer a workspace matching the recording folder's name case-insensitively; otherwise reuse/create `Live meetings` with engine `local`. Existing workspace engines are retained. `commitment_dismiss(session_id, id)` only changes in-memory state. Every catch/state change emits the pinned `copilot-commitment` payload. Approval is idempotent; failures roll back task creation. Link a known meeting ID, otherwise use `None`; schema changes and backfill are outside this slice.

Rust implementation is complete and automated gates pass; native end-to-end timing and the artifact-before-recording-stops demonstration remain pending. See [HANDOFF.md](./HANDOFF.md) for validation and the test-only bundle-resource override.

## Vision
**Adversaria** is a privacy-first, bot-free meeting notetaker for Windows and macOS (Apple Silicon) that records meeting audio locally, transcribes it on-device, and generates structured notes with a local LLM — **nothing leaves the machine**. No bot joins the call; no audio, transcript, or summary is uploaded; recordings are deleted once a meeting is successfully transcribed (a recording that couldn't be transcribed — e.g. the AI service was down — is kept on-device, clearly marked, until you retry). The destination is not "another Granola clone" but the **sovereign capture organ of lagharilabs OS**: the complete capture → memory → action loop that runs entirely on the customer's own infrastructure, for buyers (legal, healthcare, EU/sovereign, defense) who are legally or strategically barred from cloud AI.

## Principles (load-bearing — do not violate)
1. **Privacy is the product.** Default to 100% local/offline. Audio is deleted after transcription. Never add a code path that sends audio, transcripts, or summaries off-device unless the user *explicitly* opts in for that specific run and the UI says so. The webview never gets network access to the Python service — Rust talks to it via `reqwest`.
2. **Research the latest first.** Never rely on training memory for anything versioned (Tauri 2, faster-whisper/CTranslate2, uv, Ollama, MLX, Pydantic, httpx). Verify current docs/versions; when memory and a fetched source disagree, the source wins.
3. **Verify against reality.** Read the file before editing, run the tests, run the app, check the DB/config on disk. Report behavior plainly — including failures.
4. **Many small, focused files; immutability; explicit errors** at every boundary, with user-facing messages.
5. **Leave the docs better than you found them.** Update the relevant companion doc in the same change.
6. **It must work without the user touching anything.** (Founder, 2026-08-11, verbatim: _"I'm not going to do anything in the back settings. Neither are the people who will use this. If it's Qwen, Gemma, or Muse, it should work for all."_) When a value depends on the machine, the model, or the input — context window, thread count, timeouts, model choice — **compute it at runtime** from what can be measured (RAM, the prompt, the model's own `/api/show` metadata). An env var or Settings toggle is acceptable only as a **debugging override that is never required**, and per-model hardcoded tables are a bug: the next model the user installs isn't in them. A knob the user must find to get a correct note is a defect, not a feature.

## Scope
- **In:** on-device record → transcribe → summarize → store → review; dual capture (system + mic); speaker labels incl. **anonymous Speaker-N diarization of the system channel** (sherpa-onnx, on by default); multilingual/RTL summaries; meeting auto-detect; chat-with-meeting; verbatim user notes; personalization (name, vocabulary); user-editable prompt templates; Windows (WASAPI/CUDA) + macOS (ScreenCaptureKit+cpal/MLX). **(2026-07-02, all shipped in v0.3.14)** audio-file import (voice memo → notes); dark **slide export** (self-contained HTML → browser one-page PDF) + Markdown export; **meeting bundle export/import** (`*.adversaria.json`, federated fresh-id import) + backup-all/restore (Settings → Data); in-app **Knowledge Graph tab** (meetings/people/tags/owners from SQLite, zero LLM, cytoscape + infinite d3-force). **(2026-06-20)** an **opt-in cloud-LLM provider** picker (Grok / OpenRouter / any OpenAI-compatible) for users without a local GPU — **off by default, clearly labeled that the transcript leaves the device** (Principle 1); attendee-name normalization (dedup + roster grounding); calendar integration for attendee rosters — **macOS via EventKit** (zero sign-in: reads the calendars already in the Mac's Calendar app via one OS permission, no OAuth/backend) and **Google Calendar** read-only OAuth (tokens in OS keychain) as the Windows/cross-platform path — **off by default** either way. **(2026-07-10, shipped in v0.3.32)** **category→template auto-routing** (default-template summaries detect what the recording is — hint > one-word local-LLM classify > heuristic — and pick the matching template; an explicit manual pick is never overridden) + a **bidirectional interview template** (detects whether the user is interviewer or candidate); **sidebar auto-archive** (Pinned + last-N-days resting view, older meetings fold into a searchable Archive; `archive_after_days` setting), selected-meeting highlight, clear-ALL-filters, and **@person attendee search chips**. **(2026-08-05, shipped in v0.3.73)** **OS notifications, every one of them user-controllable**: the pre-meeting calendar alert (`meeting_reminder_enabled`, off by default) and the daily due/overdue **to-do digest** (`todo_digest_enabled` + `todo_digest_hour`, on by default because it shipped ungated and silently switching it off would remove a notification users already receive). The digest previously had **no setting at all** — the product must never interrupt the user in a way they cannot switch off.
- **In, working tree (2026-08-30; not yet released):** a project is the meeting-facing form of a long-lived workspace. Users can create colored project folders, file one meeting into one project, view a locally generated overview and attendee frequency across the filed meetings, manage the project's open action items, and set standing instructions. The overview is grounded only in local filed-meeting content and never browses the web. Deleting a project deletes the container and its bindings, never the meetings.
- **Out (for now):** off-device processing *as the default* (the cloud-LLM path above is strictly opt-in and labeled; local stays the default and the product's point); **Microsoft** calendar (Google read-only OAuth is built; MS is the next provider — `docs/SPEC_CALENDAR.md`); **named**-speaker identification (anonymous Speaker-N diarization IS built — mapping those labels to real identities is specced in `docs/SPEC_DIARIZATION.md`, not built); pre-meeting notes (undecided); a *signed/notarized, distributable* installer (a personal unsigned macOS `.dmg` is built — `./scripts/build-dmg.sh` — but code-signing + notarization for distribution is a hard **launch gate**, not yet done); **in-binary Pro/license gating at launch** (decided 2026-06-28: **launch free-only**, build the Merchant-of-Record + offline license path and switch Pro on ~30–60 days later — capture Pro intent via a waitlist meanwhile; the paid wedge targets regulated client-facing solos, not broad prosumers — see [STRATEGY.md](./docs/STRATEGY.md) §2026-06-28 + [docs/LAUNCH_PLAN.md](./docs/LAUNCH_PLAN.md)).

## Open decisions
- **Pre-meeting notes (calendar prep)** — read the calendar and prompt the user with prep before a meeting. _Options:_ suggested questions / agenda / attendee+topic history; or don't build. _Lean:_ undecided — clarify the exact value before committing (pairs with cross-meeting RAG + ADR-002 read-only OAuth, off by default).
- **Next project-memory slice** — surface related meetings beneath an individual note using the retrieval already present in `workspace_runs.rs`; then continue the wider workspace-screen rebuild. Project filing and ProjectView are complete in the working tree, pending founder acceptance and commit authorization.
- **LLM backend** — local default (Rapid-MLX on macOS / Ollama elsewhere) vs. an OpenAI-compatible endpoint. _Resolved 2026-06-20:_ a Settings **Provider** picker ships — Local (default) / Grok / OpenRouter / OpenAI-compatible custom; cloud is opt-in + labeled. Backend is per-request (base_url/api_key from config), no restart.
